# NOVACAB V2.1 — Ordre de migration

La V2.1 est une migration de consolidation **à appliquer en dernier** sur une base NOVACAB existante.

1. Migrations historiques `supabase-init.sql`, sécurité, TVA et modules métier déjà utilisées par l'installation.
2. `supabase/v40-dossier-access-rights.sql`
3. `supabase/v41-fix-admin-cabinet-scope.sql`
4. `supabase/v42-internal-tickets.sql`
5. `supabase/v43-security-hardening.sql`
6. `supabase/v2.1-architecture-consolidation.sql` ← **source canonique finale**

Ne pas supprimer les anciens fichiers immédiatement : ils documentent l'historique. La V2.1 rétablit une convention unique sans effacer les données.

Après migration :

- vérifier que `current_portefeuille_id()` renvoie le bon cabinet pour un utilisateur standard ;
- vérifier qu'un utilisateur du cabinet A ne lit aucune notification du cabinet B ;
- vérifier qu'un collaborateur ne voit que les dossiers autorisés ;
- exécuter `npm test` ;
- exécuter `npm run verify:architecture` ;
- exécuter `npm run build`.

### V46 — Raccordements métier → Administration

8. `supabase/v46-admin-workflow-notifications.sql` ← **à appliquer après V2.1**

Cette migration ajoute les notifications sécurisées Admin / Expert pour :
- nouvelle mission exceptionnelle créée par un collaborateur ;
- résiliation démarrée ;
- nouvelle entrée de mission ;
- nouvelle sortie de mission structurée ;
- TVA passée à « Fait ».

Les notifications sont générées côté Supabase et non par le navigateur du collaborateur.
